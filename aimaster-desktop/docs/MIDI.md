# MIDI · 화성 · 보컬 피치 편집

작곡 영역으로 확장하기 위한 기반 레이어. Cubase 의 Key Editor / Chord Track /
VariAudio 에 해당하는 세 축을 **처음부터 MIDI 2.0 · MPE 를 담을 수 있는
데이터 모델** 위에 올렸습니다.

- 모델: `src/renderer/daw/model/` (`midi.ts` · `scales.ts` · `chords.ts`)
- 편집: `src/renderer/daw/edit/` (`midi-edit.ts` · `chord-detect.ts`)
- 파일: `src/renderer/daw/io/midi-file.ts`
- 보컬: `src/renderer/daw/audio/` (`pitch-analysis.ts` · `pitch-shift.ts` · `varia-actions.ts`)
- 엔진: `src/renderer/daw/engine/instruments.ts` · `midi-input.ts`
- 입력: `src/renderer/daw/model/midi-capture.ts` · `edit/midi-record-actions.ts`
  — 건반 녹음은 [DAW.md 의 MIDI 입력 캡처](./DAW.md#midi-입력-캡처--건반을-꽂으면-연주가-파트가-됩니다)
- UI: `src/renderer/components/daw/midi/`

## 1. 왜 이런 데이터 모델인가

프로토타입에서 흔한 `{pitch, velocity(0-127), cc[]}` 모델을 쓰지 않았습니다.
나중에 MIDI 2.0 / MPE 를 얹으려면 전 세션 마이그레이션이 필요해지기 때문입니다.

| 결정 | 이유 |
|---|---|
| 모든 연속값을 **정규화 실수**(0…1, 밴드는 −1…1)로 저장 | MIDI 1.0 의 7비트, 하이레졸루션 14비트, MIDI 2.0 의 32비트가 전부 손실 없이 들어옴. 전송 규격이 넓어져도 모델은 그대로 |
| 표현 데이터를 **노트 단위**로 저장 (`MidiNote.expression`) | MPE · MIDI 2.0 은 개별 노트를 지정함. 채널 단위 모델로는 표현 자체가 불가능 |
| 피치 = 정수 키 + **부호 있는 반음 오프셋** | 마이크로튜닝, MPE 벤드, 그리고 나중에 보컬→MIDI 전사의 실제 피치 곡선을 같은 필드로 받음 |
| 커브는 `{timeSec, value}` 브레이크포인트 | 해상도와 무관. 렌더러가 필요한 만큼 리샘플 |

`pitchBend` · `pressure` · `timbre` 는 MPE 의 세 축이자 MIDI 2.0 의 per-note
컨트롤러이고, 그 외는 `cc` / `registered` 로 받습니다.

## 가이드 멜로디로 피치 보정 (`toMidi`)

스케일에 맞추는 보정은 **"부른 음에서 가장 가까운 합법적인 음"** 만 물을 수
있습니다. 한 음 낮게 부른 프레이즈는 의도한 음이 아니라 **가까웠던 엉뚱한
스케일 음**으로 갑니다.

가이드 멜로디는 그 답을 미리 줍니다. Key Editor 에 MIDI 파트를 열어 두고
`Mod+Alt+T` 를 누르면, 각 VariAudio 구간이 그 순간 울리는 가이드 노트로
튜닝됩니다.

세부 셋이 결과를 좌우합니다.

* **겹침이 가장 큰 노트가 이깁니다.** 구간이 두 가이드 노트에 걸칠 수 있는데,
  먼저 시작한 노트를 고르면 길게 끈 음이 끝에서 만난 짧은 노트로 끌려갑니다.
* **3반음을 넘으면 건너뜁니다.** 부른 음에서 5도 떨어진 가이드 노트는 거의
  언제나 정렬 실수이지 아무도 원하지 않는 보정입니다. 안전 난간입니다.
* **가이드 노트가 없는 구간은 그대로 둡니다.** 프레이즈 사이에서 가수는 혼자
  두는 것이 맞지, 아무 데나 붙이는 것이 아닙니다.

가이드 파트는 타임라인의 다른 곳에 있어도 됩니다 — 노트는
`notesInClipTime()` 으로 오디오 클립의 시계로 옮겨진 뒤 비교됩니다. 고스트
노트와 같은 함수입니다.


## 2. Key Editor

`Mod+Alt+D` → DAW → **KEY** 탭, 또는 Edit 창에서 MIDI 파트를 더블클릭,
또는 파트를 가진 트랙을 선택하고 **Enter**.

편집 대상: Note · Velocity · Pitch(벤드) · Modulation · Expression ·
Aftertouch · CC · Quantize · Humanize · Scale.

| 영역 | 구현 |
|---|---|
| 노트 그리드 | 그리기 · 선택 · 드래그 이동 · 우측 끝 리사이즈 · 마퀴 선택 (한 제스처 = Undo 1회) |
| 스케일 가이드 | 스케일 밖 음은 어둡게. Snap Pitch Editing 으로 드래그가 스케일에 붙음 |
| 하단 레인 | Velocity / Pitch Bend / Aftertouch / Timbre(CC74) / Modulation / Expression / Sustain — 드래그로 직접 그림 |
| 노트 위 곡선 | 노트별 벤드 커브를 노트 안에 그려서 MPE 데이터가 보이지 않는 일이 없게 |
| 인포 라인 | Start · Length · Pitch · Velocity · Channel · 현재 코드 · 마우스 위치 |
| 인스펙터 | Scale Assistant · Chord Editing · Quantize · Humanize · Transpose · Length · Velocity |

### 노트를 넣는 법

| 제스처 | 결과 |
| --- | --- |
| **빈 곳 더블클릭** | 노트 하나 |
| **✎ 연필** 켜고 클릭 | 노트 하나 (여러 개 찍을 때) |
| Ctrl/Cmd + 클릭 | 노트 하나 (도구를 안 바꾸고 한 번만) |
| **⌫ 삭제** 켜고 클릭, 또는 Alt + 클릭 | 그 노트 삭제 |
| **↖ 선택** 상태로 드래그 | 마퀴 선택 |
| Alt + 더블클릭 | 재생 위치 이동 |

세 가지를 고치고 나온 표입니다. 원래는 **Ctrl/Cmd+클릭 하나뿐**이었고, 화면
어디에도 그렇게 쓰여 있지 않았습니다. 실제로 재보니:

```
클릭        → 노트 0개
더블클릭     → 노트 0개   (재생 위치만 옮김)
Ctrl+클릭    → 노트 1개
```

`tool === 'draw'` 는 처음부터 노트를 그렸지만 **키 에디터 툴바에 도구를 고르는
버튼이 없었습니다.** 어레인지 창에서 먼저 도구를 바꿔본 사람만 찾을 수 있었고,
아무도 찾을 수 없는 기능은 없는 기능과 구별되지 않습니다.

그리고 그리기 스냅이 **가장 가까운 선으로 반올림**하고 있었습니다. 노트를 **옮길**
때는 그게 맞지만 **만들** 때는 틀립니다 — 칸의 절반을 넘겨 클릭하면 노트가 다음
칸, 즉 커서 오른쪽에 생깁니다. 측정값: 0.25 그리드에서 커서 2.94박 → 노트 3.000박
(클릭한 칸은 2.75박에서 시작). 지금은 **클릭한 칸으로 내림**합니다.

더블클릭이 재생 위치를 옮기던 자리는 **Alt+더블클릭**으로 옮겼습니다. 이 에디터에는
룰러가 없어서 그게 안에서 재생 위치를 옮기는 유일한 방법이었기 때문에, 없애지 않고
남겼습니다.

### Quantize / Humanize

Quantize 는 그리드 · 튜플렛 · 스윙 · **강도(Soft Quantize)** · 캐치 레인지 ·
세이프 레인지 · 랜덤화 · 길이/엔드 퀀타이즈를 지원합니다.

Humanize 는 **시드 고정 난수**입니다. `Math.random()` 을 쓰면 오프라인
바운스가 방금 들은 것과 달라지므로, 같은 시드는 항상 같은 결과를 냅니다.
그루브 항목은 강박을 살짝 당기고 약박을 미는 편향을 넣어 "노이즈"가 아니라
"사람이 친 것"에 가깝게 만듭니다.

## 2-A. 내장 악기

| 악기 | 방식 |
| --- | --- |
| **Poly Synth** | 감산 합성 |
| **Rhodes (FM)** | 2오퍼레이터 FM + 타인 + 픽업 |
| **Acoustic Guitar** | Karplus-Strong 물리 모델링 |
| **Electric Guitar** | Karplus-Strong + 픽업 공진 |
| **Drum Kit** | GM 매핑 신스 킷 — 음정이 조각을 고릅니다 |
| **Sampler (SFZ)** | 녹음 재생 — 라이브러리는 사용자가 넣습니다 |

**키 에디터 툴바의 드롭다운**에서 고릅니다. 그 드롭다운이 생기기 전까지는
`instrumentId` 가 트랙 모델에 있는데도 **모든 트랙이 `polysynth` 로 하드코딩**돼
있었습니다 — FM 에피아노는 코드에는 있고 아무도 닿을 수 없었습니다. 연필 버튼이
없어서 노트를 못 찍던 것과 같은 모양입니다.

### F11 — 악기부터 고릅니다

큐베이스의 F11 이 빠른 이유는 하나입니다: **악기를 먼저 고르고, 트랙이 거기
맞춰 생깁니다.** 여기는 반대였습니다.

- `+ 인스트루먼트` 는 무조건 `polysynth` 를 만들고 `Synth N` 이라고 이름 붙였습니다.
- 나머지 네 악기로 가는 유일한 문은 **Key Editor 안의 드롭다운**이었습니다.
- 그 에디터를 열려면 파트가 있어야 하고, 파트가 있으려면 트랙이 있어야 하고,
  트랙을 만드는 그 버튼이 항상 polysynth 를 만들었습니다.

그래서 **동작하는 악기 네 개가 실질적으로 없는 것과 구분되지 않았습니다.**
이 저장소에서 이번 세션에만 네 번째 보는 모양입니다 — 연필, 악기 드롭다운,
샘플러 로드 버튼, 그리고 이것.

`F11` 을 누르면 랙이 열립니다. 악기를 고르고 **+ 추가** 를 누르면:

| | |
|---|---|
| 트랙 이름 | 악기 이름에서 옵니다 — `Rhodes 1`, `Electric Guitar 1` |
| 번호 | 이미 있는 이름을 피해서 붙습니다 — 사이에 기타를 끼워 넣어도 두 번째 로즈는 `Rhodes 2` |
| 파트 | 4마디, 템포와 박자표에서 계산 (120bpm 4/4 → 8초, 90bpm 3/4 → 8초) |
| 그리고 | Key Editor 가 그 파트를 열고 있습니다 |

슬롯 줄마다 **편집** · **+ 파트** · **MIDI**, 그리고 악기를 바꾸는 드롭다운이
있습니다. `+ 인스트루먼트` 툴바 버튼도 **같은 창**을 엽니다 — 문이 두 개인데
서로 다르게 동작하는 게 애초에 polysynth 전용 경로가 살아남은 이유였습니다.

**+ 파트는 있는 것 뒤에 붙습니다.** 전부 0초에 떨구면 배열은 파트 하나로 보이고
소리는 네 개로 납니다.

### MIDI 내보내기 — 나가는 문이 없었습니다

`exportMidiFile` 은 임포터가 들어온 이후로 계속 있었습니다. 작성돼 있고,
셀프테스트가 돌고 있고, **앱에서 부르는 곳이 하나도 없었습니다.** .mid 를 읽고
쓰지는 못하는 DAW 는 편도입니다. 랙 슬롯의 **MIDI** 버튼이 그 문입니다.

노트는 **파트 기준 beat** 로 저장됩니다. 그래서 파트 네 개를 그냥 이어 쓰면
**전부 1마디에 쌓입니다** — 파일 크기는 멀쩡하고 내용은 엉망인 종류의 버그죠.
`trackNotesInBeats` 가 각 파트를 템포맵 위 자기 자리로 다시 앵커합니다:

```
파트 1 (0초) 의 노트 beat 0  →  beat 0
파트 2 (8초) 의 노트 beat 0  →  beat 16     (120bpm = 초당 2beat)
파트 2 (8초) 의 노트 beat 2  →  beat 18
```

앵커를 빼고 실측하면 `0, 0, 2` 가 나옵니다. 셀프테스트가 그걸 잡습니다.

### 기타는 왜 노드로 안 만들었나

Karplus-Strong 은 딜레이 라인을 감쇠 필터로 되먹이는 구조고, **딜레이 길이가 곧
음정**입니다. 다른 장치처럼 네이티브 WebAudio 노드로 먼저 만들어봤는데 안 됩니다:

> **크로미움은 피드백 루프 안의 DelayNode 를 렌더 퀀텀 하나(128 샘플, 48 kHz 에서
> 2.67 ms)로 클램프합니다.** 기타 음은 전부 그보다 짧습니다(A4 = 109 샘플). 그래서
> 음정이 클램프 값이 되어버립니다. 실측:
>
> ```
>   82.4 Hz →   67.3 Hz        440 Hz →  200.0 Hz
>  146.8 Hz → 1043.5 Hz        880 Hz →  259.5 Hz
> ```
>
> 게다가 음정만 틀린 게 아니라 **터졌습니다** — 고음역에서 피크 9.5e17.

그래서 줄을 **샘플 단위로 계산해서 버퍼로 재생**합니다. 이건 우회가 아니라 더
나은 선택입니다: 루프가 정확하고, 튜닝이 정확하고, **셀프테스트가 도는 폴리필과
앱이 도는 크로미움에서 결과가 완전히 동일합니다.** 리버브 스위트는 "여기서 초록인
게 크로미움에서의 증거가 아니다"라는 경고를 달고 살아야 하는데, 이 파일은 그럴
필요가 없습니다 — 그래프 해석이 아니라 산술이니까요.

### 튜닝 — 부호 두 개가 전부입니다

루프 지연은 세 부분이고 셋 다 셉니다:

| 부분 | 기여 |
| --- | --- |
| 딜레이 라인 | `L` 샘플 |
| 소수점 읽기 | `buf[idx+1]` 은 **한 샘플 최신**이라 `frac` 을 **뺍니다** |
| 루프 필터 | 2점 평균의 그룹 지연 = 정확히 **0.5 샘플** |

즉 주기 = `L − frac + 0.5`. 소수점 읽기의 부호를 반대로 잡으면 악기 전체가
샤프해지고, **음이 높을수록 더 틀립니다**. 실측 오차:

```
  82.41 Hz  0.0 cents        440 Hz  0.0 cents
 164.81 Hz  0.0 cents     659.26 Hz  0.1 cents
 329.63 Hz  0.0 cents        880 Hz  0.8 cents
```

E6 에서 7.7 cents 인데, 거기선 한 주기가 36 샘플이라 소수점을 넣을 자리가 없습니다.
샘플레이트의 한계지 모델의 한계가 아닙니다.

### 여기서 잰 것들

| 주장 | 실측 |
| --- | --- |
| 로즈는 세게 치면 "깡" 한다 | 어택 스펙트럴 센트로이드 457 → **744 Hz** (벨로시티 0.2 → 0.95) |
| 일렉이 통기타보다 길게 울린다 | 3초 시점 RMS **0.00497 vs 0.00002** |
| 피킹 위치는 EQ 가 아니라 콤 필터다 | 브릿지 **4041 Hz**, 가운데 **3071 Hz** |

### 노이즈에 시드를 박은 이유

이 엔진의 계약은 **바운스가 프리뷰와 같은 소리**라는 것입니다. `Math.random()`
으로 줄을 튕기면 렌더할 때마다 달라지고, 앱의 다른 어떤 것도 그걸 눈치채지
못합니다. 실제 줄도 튕길 때마다 다르지만, 그 차이는 **음의 함수**여야 합니다 —
같은 음, 같은 소리, 매번.

### 드럼은 F11 에서 고릅니다

**Drum Kit** 을 고르면 트랙 · 4마디 파트 · **GM 킷 맵**이 함께 옵니다. 맵이
같이 와야 피아노 롤이 이름 붙은 레인(킥 · 스네어 · 하이햇)이 됩니다 — 소리만
있고 맵이 없으면 숫자 벽 그대로입니다.

이 악기만 **음정이 조각을 고릅니다**: 36번은 낮은 도가 아니라 킥입니다.

슬롯 둘째 줄에 **킷**과 **패턴**이 따로 있습니다. 둘 다 장르별이고, 서로 다른
질문입니다 — 힙합 킷으로 팝 비트를 치는 건 실제로 쓸모 있는 조합입니다.

**킷**(10종): 전역 노브 다섯 개가 아니라 **조각마다** 튜닝·감쇠·레벨·팬이
바뀝니다(재즈 킥은 팝 킥을 줄인 게 아닙니다).

**패턴**(20종, 장르당 2개): 고르고 **+ 패턴** 을 누르면 4마디로 채워 들어갑니다.
차트로 작성돼서 소스에서 비트가 눈에 보이고, 변환은 스텝 시퀀서의 것을 그대로
씁니다 — 그래서 스텝 시퀀서에서 열어 편집할 수도 있습니다.

합성 방식과 킷별 실측값, 그리고 여기서 네 번 잘못 짚었던 기록은 `docs/DAW.md` 의
**드럼 맵** 절에 있습니다.

### 피아노는 왜 모델링이 아니라 샘플러인가

기타 두 대는 물리 모델링입니다. **튕긴 줄이 실제로 딜레이 라인이기 때문**에
모델이 곧 악기입니다. 피아노는 그렇지 않습니다: 해머가 미세하게 디튠된 세 줄을
때리고, 그 진동이 사운드보드의 공진을 거치고, 댐퍼가 올라간 나머지 줄이 공명으로
따라 웁니다. 그 공진들이 곧 그 피아노의 정체성입니다. 빨리 만들면 1985년
신디사이저가 나옵니다. **그래서 피아노는 녹음이고, 녹음에는 샘플러가 필요합니다.**

### 샘플러 — 정확해야 하는 두 가지

샘플 악기의 나머지는 전부 녹음의 품질이지만, 이 둘은 코드의 문제입니다.

**어느 존을 고르는가** (`zonesFor` / `pickZone`)

- 벨로시티는 노트 모델에서 0..1 로 오고 SFZ 는 1..127 로 셉니다. 변환은 **여기
  한 곳에서만** 합니다. 호출부마다 하면 가장 여린 레이어가 0 으로 반올림돼서
  영영 안 울립니다 — 셀프테스트가 잡는 항목입니다.
- 라운드로빈 카운터는 **모듈 레벨**입니다. 보이스와 함께 만들면 항상 0이라
  매번 1번 테이크가 나오고, 라운드로빈이 존재하는 이유가 그대로 사라집니다.
  (같은 건반 세 번 → `D1rr1, D1rr2, D1rr3` 인지 셀프테스트가 확인합니다.)

**얼마나 빠르게 재생하는가** (`playbackRateFor`)

`tune`(cents)과 `transpose`(semitone)는 **지수 안**에 들어갑니다:

```
rate = 2 ^ ((pitch − keyCenter + transpose + tune/100) / 12)
```

cents 를 rate 에 더하면 루트 음에서만 맞고 늘려 쓴 건반마다 어긋납니다. 실측으로
루트가 **−144 cents** 틀어지는 걸 확인했습니다.

### 라이브러리는 들어있지 않습니다

**상용 샘플은 라이선스상 넣을 수 없고**, 이 빌드 환경에서는 무료 라이브러리도
받을 수 없었습니다(모든 샘플 호스트가 차단됨). 그래서 **엔진과 SFZ 임포트만**
들어갑니다.

키 에디터에서 악기를 **Sampler (SFZ)** 로 고르면 툴바에 **♪ 라이브러리** 버튼이
생깁니다. `.sfz` 를 열면 그 파일이 가리키는 wav 를 전부 디코딩하고, 한 줄로
요약합니다 — 존 개수, 건반 범위, 벨로시티 겹, 라운드로빈, **빈 건반**, **읽지
못한 파일**. 무료 라이브러리 절반은 배포에 없는 파일을 참조하기 때문에 그런
파일은 로드를 중단시키지 않고 **세어서 보여줍니다**. 조용한 건반을 나중에
직접 발견하게 두는 것보다 낫습니다.

추천: **Salamander Grand Piano** (CC-BY, SFZ 배포).

### 앱에서 잰 것

테스트용 4파일짜리 라이브러리를 실제 앱에 로드해서 잰 값입니다. 다이얼로그만
빼고 — IPC, 경로 가드, 파일 읽기, 존 선택, 재생 속도 — 전부 실제 경로입니다.

| 항목 | 실측 |
| --- | --- |
| 로드 결과 | `TestPiano: 7존 · 건반 21–108 · 벨로시티 2겹 · 라운드로빈 2`, 읽지 못한 파일 0 |
| 음정 (7개 건반, 녹음 3개를 늘려서) | 최대 오차 **0.63 cents** |
| 라이브러리 밖 건반 (midi 12) | **무음** — 엉뚱한 음이 아니라 |
| 같은 건반 4번 | 피크 0.226 / 0.113 / 0.226 / 0.113 — 두 테이크가 번갈아 |
| 벨로시티 0.2 vs 0.9 | 피크 0.040 vs 0.113 — 다른 레이어 |

세 가지를 일부러 망가뜨려서 전부 잡히는 것을 확인했습니다: 재생 속도 지수의
부호를 뒤집으니 루트 건반만 맞고 나머지는 ±400 cents로 튀었고(루트만 테스트했다면
못 봤을 겁니다), 라운드로빈 카운터를 고정하니 네 번 다 0.226이 나왔고, 건반 범위
검사를 빼니 midi 12가 소리를 냈습니다.

### 로드는 재생 엔진을 기다리지 않습니다

처음 만들었을 때 라이브러리 버튼은 `dawRuntime.context` 가 있어야 동작했습니다.
그 컨텍스트는 **처음 재생을 눌러야** 생깁니다. 그래서 앱을 켜고 제일 먼저
"내 피아노 불러오기"를 누른 사람은 *"오디오 엔진이 아직 준비되지 않았습니다"* 를
보는데, 이 에디터에서 그 엔진을 켤 방법은 없습니다. 참인데 쓸모없는 메시지죠.

지금은 디코딩 전용 컨텍스트를 따로 만듭니다. 그리고 그건 **오프라인**입니다 —
실제 `AudioContext` 를 만들면 출력 장치를 여는데, 출력이 없는 머신에서 그 호출이
**렌더러 스레드를 통째로 멈춥니다**(여기서 실측: 창이 멈춘 뒤 돌아오지 않음).
라이브러리 로드가 그런 일을 할 수 있으면 안 됩니다. 대가는 샘플레이트가 다를 때
리샘플 한 번인데, 어차피 루트가 아닌 모든 음을 리샘플하는 악기입니다.

다이얼로그(`pickSfz`)와 로더(`loadLibraryFrom`)도 갈라 놨습니다. `electronAPI` 는
contextBridge 가 **얼려버려서** 페이지에서 다이얼로그를 스텁할 수 없고, 헤드리스
X 서버에서 네이티브 다이얼로그는 영영 돌아오지 않습니다 — 붙여 두면 로드 경로를
사람 손 없이는 검증할 수 없습니다.

**아무것도 로드하지 않은 샘플러는 소리가 나지 않습니다 — 일부러 그렇습니다.**
대체 톤을 울리면 비어 있는 샘플러가 동작하는 것처럼 들리고, 그러면 첫 번째
버그 리포트가 "피아노에서 삐 소리가 난다"가 됩니다.

### 지원 범위

읽습니다: `<global>` / `<master>` / `<group>` / `<region>` 상속, `sample`,
`default_path`, `key` / `lokey` / `hikey` / `pitch_keycenter`, `lovel` / `hivel`,
`tune` / `transpose` / `volume` / `pan`, `seq_position` / `seq_length`,
`loop_mode` / `loop_start` / `loop_end`, `trigger`, `ampeg_release`.

아직 안 읽습니다: 필터·LFO·`offset`·`ampeg` 의 나머지 단계. **릴리스 트리거
샘플은 파싱하고 리포트에 세지만 아직 울리지는 않습니다.** 파서가 못 읽은
opcode 는 버리지 않고 이름별로 세어서 `unsupported` 에 담아둡니다.

경로는 메인 프로세스의 `samplePathIn()` 을 지나야 읽힙니다. 라이브러리 루트
밖으로 나가는 `..`, 절대 경로, 널 바이트는 거부합니다 — `.sfz` 는 결국
**남이 준 파일**이고, 그 안의 문자열이 파일 시스템 어디든 가리킬 수 있습니다.

## 3. MIDI 파일 · 인스트루먼트

`Mod+Shift+I` 또는 DAW 툴바의 **MIDI 가져오기** 로 `.mid` 를 읽습니다.
포맷 0/1, 러닝 스테이터스, 템포 맵(리타르단도 포함), 박자표, 트랙명 지원.

**MPE 파일은 자동 감지**해서 채널별 벤드·프레셔·CC74 를 그 채널에서 울리는
노트의 per-note 표현으로 옮깁니다. 일반적인 임포터가 버리는 정보입니다.

내장 인스트루먼트는 위 표의 다섯 종이며, **노트마다 보이스를 하나씩** 만듭니다.
그래야 벤드·프레셔·팀브르가 그 노트에만 걸립니다. 전부 오프라인 바운스에서도
동일하게 렌더됩니다 — 신스는 네이티브 WebAudio 노드, 기타는 미리 계산한 버퍼,
샘플러는 디코딩된 `AudioBuffer` 입니다.

## 4. Chord Track

세션은 화성을 **구조화된 심볼**(근음 · 성질 · 베이스)로 들고 있습니다.
텍스트 라벨이 아니라 데이터이므로 변환이 함수입니다.

- 코드 감지: `Mod+Shift+C` — 열린 MIDI 파트를 마디 단위로 읽어 코드 트랙 생성
- 리하모나이즈: `Mod+Alt+J` — 3화음 → 7화음, 도미넌트 앞에 관련 ii 삽입
- 그 외 변환: 트라이톤 대리, 단순화, 이조, 코드→스케일 추천

```
Cmaj7 → Am7 → Dm7 → G7        (감지)
Cmaj7 → Am7 → Dm7 → Dm7 → G9  (extend + insertTwoFive)
Cmaj7 → Am7 → Dm7 → C#7       (tritone)
```

미래의 "여기 코드 좀 재즈스럽게 바꿔" 는 이 함수들을 호출하는 형태가 됩니다.
AI 가 오디오를 추측하는 게 아니라, 프로젝트가 이미 알고 있는 화성을
결정론적으로 변형하는 것이라 무엇이 바뀌었는지 항상 설명 가능합니다.

### 코드 레인 — 타이핑이 기본 입력

오랫동안 코드 트랙은 **읽을 수만 있는 데이터**였습니다. MIDI 파트에서 감지하는
것이 유일한 입력 경로였고, 감지기가 잘못 읽은 코드는 잘못된 채로 남았습니다.
이제 EDIT 창의 어레인지 레인 아래에 코드 레인이 있습니다.

입력은 **텍스트 상자**입니다. 근음 × 성질 피커가 아닙니다.

- `Cmaj7` 은 피커로 12 × N 번 클릭이고 여기서는 다섯 타건입니다
- 음악가는 이미 그 철자를 압니다
- `parseChord` 가 엄격해서 오타는 **문장으로 돌아옵니다** — 조용히 틀린 코드가
  들어가지 않습니다 (`'Hmaj9999' 를 코드로 읽지 못했습니다 — C · Am · G7 …`)

빈 상자는 오타가 아니라 **취소**입니다. 상자를 비우는 건 그만두겠다는 뜻이지
잘못된 코드가 아니고, 빈 문자열을 코드가 아니라고 혼내는 건 도구를 적대적으로
느끼게 만듭니다.

코드는 어레인지 섹션과 같은 규칙을 씁니다 — **시작만 저장하고 끝은 다음 코드의
시작**입니다. 그래서 빈틈과 겹침이 표현 불가능하고, 경계를 끄는 게 한 번의
편집이며, 이웃을 추월할 수 없습니다(추월하면 진행이 조용히 재배열됩니다).

`Alt+H` 로 재생 위치에 C 를 놓고 더블클릭해 고쳐 씁니다. 8마디 뼈대 버튼은
작곡가가 플러스를 열여섯 번 누르는 대신 뼈대 위에 타이핑하라고 있습니다.

## 5. 보컬 피치 편집 (VariAudio 계열)

`Mod+Alt+P` 로 재생 위치의 오디오 클립을 분석하고, `Mod+Alt+U` 로 에디터
스케일에 맞춰 보정합니다. **원본 파일은 건드리지 않고** 새 렌더를 만들어
클립이 그것을 가리키게 하므로 Undo 로 완전히 되돌아갑니다.

측정하는 것 — 구간별로:

| 항목 | 방법 |
|---|---|
| Pitch | YIN (누적 평균 정규화 차분) + 포물선 보간 → 센트 단위 |
| Timing | 무성 구간 · 피치 도약 기준 세그먼테이션 |
| Vibrato | 드리프트를 뺀 곡선의 자기상관 → 4–8 Hz 대역의 속도 + 깊이(센트) |
| Pitch Drift | 센트 곡선의 최소자승 기울기 (센트/초) |
| Formant | 측정이 아니라 **편집 파라미터** (렌더에서 그레인 리샘플로 적용) |

편집 파라미터는 Cubase 의 스마트 컨트롤과 같은 축입니다:
`pitchOffsetCents` · `vibratoScale` · `driftScale` · `curveScale` ·
`formantSemitones` · `timeOffsetSec`.

렌더는 **TD-PSOLA** 입니다. 그레인의 파형(=성도 공명)을 그대로 두고 배치
간격만 바꾸므로 피치를 올려도 목소리가 다람쥐가 되지 않습니다. 포먼트는
그레인 **내용**을 리샘플해서 따로 움직입니다 — 두 축이 깨끗하게 분리됩니다.

```
피치   ← 합성 주기 (그레인 간격)
포먼트 ← 그레인 리샘플
타이밍 ← 어떤 분석 그레인을 참조하는가
```

### VOCAL 창 — 노트 하나씩

분석기도 렌더러도 오래전부터 동작했습니다. 없었던 건 **찾아낸 것을 보는 방법**
입니다. 단축키는 클립 전체를 스케일에 맞추고 "12개 구간"이라고 알려 줄 수
있었는데, 이 기능이 실제로 하는 유일한 일에 대해 그건 틀린 단위입니다:
**테이크는 괜찮고 두 노트가 플랫하다.**

`Shift+Alt+V` 로 재생 위치의 클립이 블롭 에디터에서 열립니다. 화면에는 세 가지가
그려지고, 그 차이가 요점입니다.

| | |
|---|---|
| **회색 선** | 실제로 부른 것 — 곡선도 비브라토도 전부 |
| **블롭** | 가수가 겨냥한 음, 그리고 끄는 손잡이 |
| **밝은 선** | 렌더가 만들어 낼 것 |

편집이 없으면 두 선이 겹칩니다. 그게 정직한 기본 상태이고, **부른 선을 절대
숨기지 않는 이유**입니다 — 자기 출력만 보여 주는 피치 에디터는 반박할 수가
없습니다.

드래그는 기본으로 반음에 스냅하고 `Alt` 를 누르면 스냅이 풀립니다. "음에 올려"
와 "4센트만 밀어"는 둘 다 진짜 편집이고, 후자는 격자 위에서 표현이 안 됩니다.
여러 노트를 골라 끌면 **전부 같은 음정만큼** 움직입니다 — 한 음으로 모으는 건
아무도 원하지 않는 편집이니까요.

#### 렌더를 두 번 하면 두 번 보정되던 버그

`renderClipPitch` 는 클립을 새로 렌더한 파일로 옮기면서 세그먼트의 편집을
**그대로 두고 있었습니다.** 한 번 렌더하면 정확합니다. 그런데 **또** 렌더하면 —
UI 가 생기면 "한 노트만 더 고치고 렌더" 가 정상적인 작업 방식이 됩니다 — 이전의
모든 보정이 이미 그것이 적용된 오디오 위에 한 번 더 적용됩니다. 40센트 올린
노트가 80센트 샤프로 끝납니다.

`bakeSegment` 가 고칩니다: 렌더가 끝나면 편집이던 것은 **녹음의 일부**가 됐으므로
`measured` 로 옮겨 가고 편집은 초기화됩니다. 곡선까지 다시 씁니다 —
`vibratoScale` 이 이미 오디오에 찍혔는데 원래 흔들림을 `measured` 에 남겨 두면
에디터가 존재하지 않는 연주를 그리고, 다음 렌더가 그걸 또 한 번 눌러 버립니다.

양쪽 방향 모두 조용히 실패하는 종류라 테스트가 두 가지를 다 붙듭니다:
굽지 않으면 정말로 두 배가 되는가, 그리고 구우면 같은 순간이 같은 음정으로
남는가.

## 6. 테스트

```
pnpm --filter @aimaster/desktop test:midi    # 모델 · 스케일 · 코드 · 편집 · SMF (41)
pnpm --filter @aimaster/desktop test:varia   # 피치 분석 · 편집 모델 · PSOLA 렌더 (20)
pnpm --filter @aimaster/desktop test:daw-engine  # MIDI 렌더 증명 포함 (17)
pnpm --filter @aimaster/desktop test:vocal-chord # 세그먼트 · 베이크 · 코드 편집 (37)
pnpm --filter @aimaster/desktop test:instruments # 줄 모델 튜닝 · 로즈 · 감쇠 (11)
pnpm --filter @aimaster/desktop test:sampler # SFZ 파싱 · 존 선택 · 재생 속도 · 경로 (23)
pnpm --filter @aimaster/desktop test:instrument-rack # F11 랙 · 파트 배치 · .mid 왕복 (14)
pnpm --filter @aimaster/desktop test:drumkit # 킷 매핑 · 스펙트럼 · 감쇠 · 결정성 (17)
pnpm --filter @aimaster/desktop test:drum-presets # 장르 킷 10종 · 차별화 · 인덱스 안정성 (16)
pnpm --filter @aimaster/desktop test:drum-patterns # 장르 패턴 20종 · 타점 위치 · 반복 (17)
```

숫자로 검증하는 항목:
- 220 / 440 Hz 톤을 **10센트 이내**로 읽는가
- 5 Hz · 40센트 비브라토가 그대로 측정되는가
- +2 반음 편집이 실제로 장2도만큼 올라가는가 (렌더 후 재측정)
- 45센트 플랫한 노트가 목표 음정에 붙는가
- 편집하지 않은 구간이 **비트 단위로 동일**한가
- MPE 파일의 채널 벤드가 노트별 표현으로 옮겨지는가
- 노트별 벤드가 렌더된 오디오의 주파수를 실제로 바꾸는가 (Goertzel 측정)
- 절대 경로가 절대 경로로 남는가 (`/lib/piano` 가 `lib/piano` 가 되면 macOS·리눅스에서 못 찾습니다)
- 가장 여린 벨로시티 레이어에 닿는가 (velocity 0.001 이 존 0개를 매치하면 실패)
- 같은 건반을 세 번 치면 세 테이크가 나오는가 (라운드로빈이 얼어붙지 않는가)
- 루트 건반의 재생 속도가 cents 오차 없이 1.0 인가
- `<region>` 이 `<group>` 의 벨로시티 범위를 물려받는가
- 파트 두 개를 내보내면 두 마디로 나오는가 (앵커를 빼면 `0, 0, 2`)
- 내보낸 .mid 를 다시 읽으면 같은 노트가 나오는가 (`60@0 64@16 67@18`)
- F11 이 랙을 열고, 툴바 버튼이 **같은 창**을 여는가
- 킥은 낮고 하이햇은 높은가 (센트로이드 157 Hz vs 9069 Hz)
- 클로즈드 하이햇은 멈추고 오픈은 울리는가
- 톰이 킷이 적어둔 순서대로 음정이 올라가는가
- 같은 히트를 두 번 렌더하면 **비트 단위로 같은가** (바운스 = 프리뷰)
- 킷을 추가하면 **드럼 맵이 같이 오는가** (신스에는 안 붙는가)
- **열 개 킷이 정말 열 개인가** (두 킷씩 전부 비교, 최소 5% 차이)
- 힙합 킥이 808 인가 (K-POP 킥의 2.5배 이상 길게)
- 재즈 라이드가 자기 킥보다 크고 길게 울리는가
- 로파이가 정말 어두운가 (K-POP 하이햇 에어의 1/3 이하)
- `kit 1 === 재즈`, `kit 10 === J-POP` — 인덱스가 밀리면 저장된 세션이 전부 옆 킷
- 백비트 스네어가 정말 2·4 인가 · 4온더플로어가 정말 네 박 전부인가
- 트랩에 롤이 있고, 롤이 **자기 스텝 안에** 머무는가 (넘치면 다음 타점이 밀립니다)
- 재즈가 셋잇단 그리드인가 (16분 그리드로는 표현 못 하는 위치)
- 한 차트 안에 길이가 다른 줄이 있는가 (드럼 하나만 조용히 잘립니다)
- 반복이 이어 붙는가, 1마디에 겹쳐 쌓이는가

여덟 가지를 **일부러 망가뜨려서** 여덟 개 다 잡히는 것을 확인했습니다. 그중 하나는
처음에 **안 잡혔습니다** — 체크가 `openSampleLibrary` 의 첫 등장을 찾았는데 그게
import 문이라 버튼 근처를 전혀 안 보고 있었습니다. 체크를 고쳤습니다.

## 7. 남은 작업

1. MIDI 내보내기의 MPE 모드 (현재 내보내기는 MIDI 1.0 채널 메시지)
2. 보컬 → MIDI 전사 (분석 결과가 이미 노트 후보라 연결만 남음)
3. 노트를 비트로 — 지금 노트는 초 단위라 템포 맵을 따라가지 않습니다
4. 블롭의 **가로** 드래그 — `timeOffsetSec` 는 모델도 렌더러도 지원하지만
   에디터에서는 세로(피치)만 끌 수 있습니다
5. 코드 레인에서 코드 → 스케일 추천을 바로 띄우기 (`chordScales` 는 이미 있음)
