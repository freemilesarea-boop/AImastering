# Warp

오디오가 세션 템포를 따라오게 만드는 층입니다. Ableton 에서 가져온 개념이고,
루이에서는 **마커 → 비트** 매핑 하나로 전부 파생됩니다.

---

## 데이터 모델: 왜 초가 아니라 비트인가

워프 마커는 **소스 파일의 한 순간**을 **음악적 위치(비트)** 에 묶습니다.

```ts
interface WarpMarker { id; sourceSec: number; beat: number }
```

초로 적어두면 템포가 바뀔 때마다 전부 다시 써야 하고, 같은 진실이 두 벌
존재하면 템포 맵은 반드시 썩습니다. 비트는 정의상 템포 독립적입니다.

여기서 나머지가 전부 따라옵니다.

* 세션 템포가 비트를 초로 바꾸므로, **템포를 바꾸는 순간 워프된 클립이
  스스로 다시 정렬**됩니다. 재렌더 여부를 묻는 대화상자가 필요 없습니다.
* 마커 사이는 선형이므로 한 구간 안에서 스트레치 비율이 상수입니다. 렌더러가
  싸게 걸어갈 수 있습니다.
* 바깥쪽은 가장 가까운 구간의 비율을 연장합니다. 마지막 마커 뒤로 트림된
  클립도 재생됩니다.

`followTempo: false` 로 두면 클립이 자기 `baseBpm` 을 지킵니다 — 원샷이나
효과음처럼 늘어나면 안 되는 소재용입니다.

## 맵

```
buildWarpMap(warp, sessionBpm) → { source[], dest[], rates[] }
sourceToDest(map, s)   파일의 한 순간 → 클립 안에서 들리는 시각
destToSource(map, d)   그 반대 — 렌더러가 쓰는 방향
rateAt(map, d)         그 지점의 국소 스트레치 (소스 초 / 목적 초)
```

맵은 **단조 증가**가 보장됩니다. `moveMarker` 는 이웃 마커 사이로 비트를
클램프합니다 — 마커가 이웃을 넘어가면 오디오가 거꾸로 재생돼야 맵이
성립하기 때문입니다. 셀프테스트가 −1 s 부터 5 s 까지 훑으며 확인합니다.

## 타임 스트레치: WSOLA

시간이 변할 때 피치는 변하면 안 되므로 `playbackRate` 는 선택지가 아닙니다.
DAW 의 워프에는 WSOLA(waveform-similarity overlap-add)가 맞습니다 — 시간
영역이라 트랜지언트가 뭉개지지 않고, 페이즈 보코더의 일부 비용이며, 비율
1에서 정확히 투명합니다.

출력 프레임마다:

1. 워프 맵이 이 순간이 소스의 어디를 읽는지 알려줍니다.
2. 그건 **명목 위치**일 뿐입니다. 그대로 복사하면 임의의 위상에서 파형 두
   개를 이어 붙여 버즈가 납니다. 그래서 방금 쓴 프레임을 가장 자연스럽게
   이어가는 오프셋을 주변에서 찾습니다 — 이 유사도 검색이 전부입니다.
3. Hann 창 50 % 오버랩으로 겹쳐 더합니다. 정확히 1로 합해지므로 정규화
   패스가 필요 없습니다.

검색은 coarse-to-fine (스텝 4 → ±4 스텝 1) 입니다. 전수 검색은 4배 비싸고,
상관 피크는 coarse 결과에서 몇 샘플 이상 떨어지지 않습니다.

### 스테레오는 계획을 공유한다

`planStretch` 와 `renderStretch` 가 분리되어 있습니다. 채널마다 따로 검색하면
읽기 위치가 몇 샘플씩 어긋나고, 몇 샘플의 상대 지연은 **스테레오 이미지 붕괴**로
들립니다. 그래서 모노 합에서 계획을 한 번 세우고 모든 채널에 같은 위치를
적용합니다.

### 모드는 창 길이 프리셋이다

Ableton 의 워프 모드는 사실 창/검색 프리셋이고, 네 가지 알고리즘인 척하는
것보다 그렇게 말하는 편이 쓸모 있습니다.

| 모드 | 창 | 검색 | 쓰임 |
|---|---|---|---|
| BEATS | 23 ms | 6 ms | 드럼 — 어택 유지 |
| TONES | 46 ms | 12 ms | 단선율 · 기본값 |
| TEXTURE | 93 ms | 없음 | 패드/노이즈 — 순수 OLA, 부드럽지만 번짐 |
| COMPLEX | 46 ms | 23 ms | 풀믹스 — 넓은 검색 |

## 재생: 왜 미리 렌더링하는가

이 DAW 의 엔진 규칙은 "네이티브 WebAudio 노드만" 입니다. 라이브 재생과 오프라인
바운스가 같은 그래프여야 결과가 비트 단위로 같기 때문입니다. 타임 스트레치는
네이티브 노드로 표현할 수 없으므로, 워프는 규칙을 **다른 방식으로** 지킵니다 —
스트레치를 **한 번** 버퍼로 렌더링하고, 재생은 평범한 `AudioBufferSourceNode`
로 남습니다. 라이브와 오프라인이 같은 샘플을 읽으므로 여전히 정확히 일치합니다.

캐시 키는 (파일, 클립 구간, 템포, 모드, 마커) 입니다. 템포를 바꾸면 키가
바뀌어 다시 렌더링되고, 클립을 타임라인에서 **옮기거나 게인을 바꾸면 다시
렌더링되지 않습니다**.

## 템포 변경

타임라인은 초로 저장되지만 **편곡은 음악적**입니다 — 템포가 바뀌어도 9마디는
9마디여야 합니다. 그래서 `setSessionTempo` 는

* 모든 클립의 시작 위치를 템포 비율로 스케일하고,
* 늘어날 수 있는 것의 길이도 스케일합니다 — MIDI 파트는 항상(노트·컨트롤러
  포함), 오디오 클립은 워프가 켜져 있고 따라올 때만,
* 오토메이션과 코드 트랙도 함께 옮깁니다.

따라올 수 없는 단 하나가 **워프가 꺼진 오디오 클립**입니다. 위치는 음악적이니
옮기되 길이는 그대로 두고, **그 클립의 id 를 돌려줍니다** — 사용자가 귀로
발견하게 두지 않고 UI 가 말해줍니다.

## Auto-Warp

`autoWarp` 는 감지된 트랜지언트마다 마커를 찍고 그리드에 스냅합니다. 템포
추정치가 각 온셋의 명목 비트를 정하고, 스냅이 연주자의 타이밍 오차를
제거합니다 — 그게 "그리드에 맞춘다"의 정확한 의미입니다.

같은 그리드 칸에 스냅되는 온셋(플램 등)은 버립니다. 한 비트에 마커 두 개는
0으로 나누기입니다.

템포는 온셋 간격을 히스토그램으로 묶어 최빈 구간에서 추정하고, 70–180 BPM
범위로 접습니다 — 8분음표에 락된 검출기도 음악가가 말할 템포를 보고합니다.

## UI

WARP 창은 클립을 **음악적 시간**으로 그립니다. 파형이 워프 맵을 거쳐
렌더링되므로 보이는 것이 곧 들리는 것이고, 그리드는 고정된 채 오디오가 그에
맞서 움직입니다. 마커를 그리드 선으로 끄는 동작이 문자 그대로 "이 타격을
비트 위로 당긴다"가 됩니다.

| 동작 | 결과 |
|---|---|
| 마커 드래그 | 그 순간을 다른 비트로 |
| 더블클릭 | 40 ms 안의 트랜지언트에 스냅해 마커 추가 |
| Alt+클릭 | 마커 삭제 |

버튼: **Warp to Tempo**(마커 2개, 상수 비율 — 루프 대부분이 이 경우),
**Auto-Warp**, **Unwarp**, 모드 4종, FOLLOW TEMPO 토글.

## 테스트

```
pnpm --filter @aimaster/desktop test:warp
```

33개 검사. 맵 왕복과 단조성, 마커 클램프, auto-warp 그리드 스냅, 440 Hz 를
2배로 늘려도 440 Hz(YIN 으로 측정), 절반으로 줄여도 그대로, 스테레오 두
채널이 완전히 비례 유지, 클릭 트레인을 180 BPM 으로 워프하면 온셋이 실제로
0.333 s 간격에 떨어지는지(재검출로 확인), 그리고 **실제 오프라인 엔진 렌더** —
소스가 4초뿐인 클립이 8초까지 울리고 그 지점의 피치가 여전히 440 Hz.

## 한계

* 스트레치 비율이 8× 를 넘거나 1/8 아래로 가면 검증이 경고합니다. 그 너머는
  스트레칭이 아니라 사운드 디자인입니다.
* 세션 템포는 하나의 값입니다. 템포 트랙(곡 중간 템포 변화)은 아직 없습니다.
