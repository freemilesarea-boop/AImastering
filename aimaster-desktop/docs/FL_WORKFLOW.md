# FL Studio 레이어 — Step Sequencer · Pattern · Piano Roll 도구

FL에서 가져올 것은 음질도 기능 목록도 아니고 **제작 속도**입니다. 세 가지가
그걸 만듭니다.

---

## 1. Step Sequencer (Channel Rack)

### 왜 피아노 롤로 충분하지 않은가

드럼 파트는 **악기마다, 스텝마다 예/아니오** 하나입니다. 버튼 격자는 그 질문에
사각형을 끌어 그리는 것보다 마흔 배쯤 빨리 답합니다. 나머지 DAW는 이미 전부
`MidiNote` 로 말하므로, 이 모듈의 진짜 일은 **변환**입니다 — 격자가 들어가고
노트가 나옵니다.

### 쓸 만한 스텝 시퀀서와 장난감을 가르는 네 가지

전부 그 변환 안에 있습니다.

| | 없으면 |
|---|---|
| **스텝별 벨로시티** | 모든 히트가 똑같은 1981년 드럼머신 |
| **스윙** | 패턴은 있고 그루브는 없음 |
| **넛지** | 스네어 하나를 뒤로 미는 데 격자 전체를 옮겨야 함 |
| **래칫** | 모든 필을 손으로 그려야 함 |

스윙은 홀수 스텝을 스텝 길이의 일부만큼 늦춥니다. 넛지는 **격자를 움직이지 않고**
한 스텝만 옮깁니다(셀프테스트가 `stepTime` 은 그대로임을 확인). 래칫은
**자기 스텝 안에서** 나눠 울리므로 롤이 다음 히트를 밟지 않고, 첫 히트 뒤로
갈수록 살짝 여려집니다 — 안 그러면 기계 소리가 납니다.

### 확률은 결정론적이다

`(seed, 채널, 스텝)` 해시로 판정합니다. 같은 패턴은 언제 재생해도 같게
울리므로, **바운스가 승인한 그 테이크를 재현**합니다. 편집 중에는
`ignoreProbability` 로 그린 그대로 볼 수 있습니다.

### 유클리드 채우기

히트를 격자에 최대한 고르게 뿌립니다(Bresenham). 16스텝에 3히트를 넣으면
트레시요(0·5·10)가 그냥 나옵니다 — 대중음악 절반의 밑바닥에 깔린 그 패턴입니다.

### 되돌리기도 된다

`notesToSteps` 는 노트를 가장 가까운 슬롯에 접고, **격자가 표현하지 못한 나머지는
넛지로 남깁니다.** 연주의 타이밍이 침묵당하지 않습니다.

## 2. Pattern — 한 번 쓰고 여러 번 놓는다

### 복사된 클립과 배치된 패턴의 차이

타임라인에서는 똑같아 보이고 동작은 완전히 다릅니다. 복사된 클립의 틀린 음을
고치면 **코러스가 나오는 여덟 군데 중 한 군데**를 고친 것입니다. 패턴에서 고치면
전부 고쳐집니다. 애초에 노트의 사본이 하나뿐이었으니까요.

이게 프로젝트 만드는 방식을 바꾸는 유일한 FL 아이디어라고 봅니다.

### 구현은 일부러 작게

클립에는 배치에 필요한 게 이미 다 있습니다 — 위치, 길이, 트랙. 추가된 건 링크
하나뿐입니다.

```
clip.patternId → 노트는 저쪽에 있다
```

노트를 **읽는** 모든 곳은 `clipNotes()` 를, **쓰는** 모든 곳은 `writeClipNotes()`
를 지나고, 그 둘이 대상이 클립인지 뒤의 패턴인지 판단합니다. 그래서 변경이 모든
호출부가 아니라 **함수 두 개**로 끝났습니다.

### 잃을 수 없게 만든 것

* **패턴을 지워도 음악은 안 지워집니다.** 삭제 전에 모든 배치를 링크 해제해
  각자 노트 사본을 줍니다. 패턴을 잃는 것이 연주를 잃는 것이면 안 됩니다.
* **링크 해제는 탈출구입니다.** 코러스 하나만 엔딩이 달라져야 하는 순간, 그건
  더 이상 같은 패턴이 아닙니다.
* 배치는 세션 템포에 맞춰 **길이가 재계산**됩니다(패턴은 자기 `baseBpm` 을 압니다).

## 3. Piano Roll 도구

FL의 피아노 롤이 나은 이유는 노트를 예쁘게 그려서가 아니라, **한 제스처를 한
마디의 음악으로 바꾸는 동작 몇 개**가 있어서입니다. 전부 `MidiNote[]` 위의 순수
함수입니다.

| 도구 | 하는 일 |
|---|---|
| **Chord stamp** | 코드 모델의 보이싱을 한 번에 씁니다 (open 보이싱 포함) |
| **Arpeggiate** | 눌린 코드를 런으로 (up/down/updown/random, 옥타브 스택) |
| **Strum** | 블록 코드를 손이 친 것처럼 |
| **Slide** | 앞 노트에서 벤드해 들어옵니다 |
| **Flam** | 히트 하나가 그레이스 노트 + 히트로 |
| **Scale snap** | 벗어난 노트를 조성 안으로 |

### 세부가 결과를 만든다

* **아르페지오는 겹치는 노트만 코드로 봅니다.** 멜로디를 통과시키면 멜로디가
  나와야지 쓰레기가 나오면 안 됩니다. `chordGroups` 가 그걸 결정합니다.
* **updown 은 전환점을 두 번 치지 않습니다.** 안 그러면 런이 아니라 더듬거림이
  됩니다.
* **스트럼은 끝이 함께 끝납니다.** 기타리스트의 손가락은 차례로 닿지만 코드는
  하나로 울립니다. 각 노트를 자기 오프셋만큼 짧게 만들면 잘린 소리가 납니다.
* **랜덤 아르페지오는 시드가 있습니다.** 렌더할 때마다 달라지면 승인한 테이크를
  재현할 수 없습니다.

### 슬라이드가 특수 노트 타입이 아닌 이유

FL에서는 특수한 노트 종류지만, 여기서는 그럴 필요가 없습니다. **MIDI 2.0 모델이
이미 노트별 피치벤드를 들고 있기** 때문입니다. 슬라이드는 대상 노트 위의
피치벤드 곡선이고, 그래서 내보내기에 살아남고, 코드 안에서 노트별로 작동하고,
플레이어에 특수 분기가 필요 없습니다.

7반음을 넘는 도약은 건너뜁니다. 옥타브를 미끄러지는 건 레가토가 아니라
포르타멘토 효과이고, 실수로 그러면 고장난 소리로 들립니다.

## 테스트

```
pnpm --filter @aimaster/desktop test:fl
```

31개 검사. 스윙이 다운비트를 안 건드리는지, 넛지가 격자를 안 옮기는지, 래칫이
자기 스텝을 안 넘는지, 확률이 두 번 재생해도 같은지를 **생성된 노트 시각으로**
확인합니다. 패턴은 **배치 하나를 고치면 나머지 둘도 바뀌는지**, 패턴을 지워도
클립이 노트를 유지하는지 — 이게 깨지면 패턴이 존재할 이유가 없으므로 가장 중요한
검사입니다. 도구는 스트럼이 함께 끝나는지, updown이 전환점에서 더듬지 않는지,
멜로디가 아르페지에이터를 통과해도 멜로디인지, 슬라이드가 진짜 벤드 데이터이고
옥타브 도약은 건드리지 않는지.
