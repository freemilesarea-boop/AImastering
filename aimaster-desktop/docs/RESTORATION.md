# Restoration — Noise Reduction & De-click

iZotope RX 계열의 복원 철학을 DAW 안으로 가져온 층입니다. 두 도구가 하나의
원칙을 공유합니다: **먼저 측정하고, 그 다음에 처리한다.** 디노이저는 학습한
프로파일 없이는 돌지 않고, 디클리커는 무엇을 찾았는지 목록으로 보여준 뒤에야
손을 댑니다. 복원이 망가지는 건 언제나 눈감고 처리를 걸었을 때입니다.

---

## 1. Noise Reduction

### 왜 기존 denoise 플러그인으로는 안 되는가

믹서의 `denoise` 인서트는 광대역 익스팬더입니다 — 임계값 아래를 밀어내립니다.
라이브에서는 맞는 도구지만 복원에는 틀린 도구인데, **노이즈가 무엇인지 모르기
때문**입니다. 6 kHz 히스와 120 Hz 험이 같은 처리를 받고, 조용하고 음악적인
것들이 노이즈와 함께 벌을 받습니다.

### 학습식 감산

사용자가 **노이즈만 있는 순간**을 선택합니다 — 테이크가 시작되기 전의 룸톤.
분석기가 그 구간의 스펙트럼을 빈 단위로 측정합니다.

```ts
interface NoiseProfile {
  mean: Float32Array;       // 빈별 평균 크기
  deviation: Float32Array;  // 빈별 표준편차 — 노이즈 플로어가 얼마나 흔들리는가
  fftSize; hopSize; sampleRate; frames; durationSec;
}
```

임계값은 `mean + sensitivity × deviation` 입니다. 편차를 함께 저장하는 이유는,
평균만으로는 "이 정도 흔들림은 정상"과 "이건 신호다"를 구분할 수 없기
때문입니다.

프로파일 학습 시 STFT의 **제로 패딩과 겹치는 앞뒤 프레임은 제외**합니다.
그 프레임들은 반쯤 무음이라 평균을 끌어내립니다.

### 뮤지컬 노이즈를 막는 세 가지

순진한 스펙트럼 감산의 고질병은 **뮤지컬 노이즈**입니다 — 고립된 빈들이
무작위로 살아남아 지저귑니다. 세 가지가 함께 막습니다. 하나라도 빠지면 들립니다.

1. **플로어를 둔 오버서브트랙션 (Berouti).** 측정치보다 더 빼되, 절대
   `reductionDb` 아래로는 내리지 않습니다. **노이즈 플로어에 뚫린 구멍은
   원래 노이즈보다 더 잘 들립니다.**
2. **빈 방향 스무딩.** 빈마다 튀는 게인 곡선이 곧 지저귐의 정체입니다. 곡선을
   부드럽게 하면 메커니즘 자체가 사라집니다.
3. **시간 방향 스무딩.** 프레임 사이에서 게인이 튀지 않고 램프합니다.

> 셀프테스트는 총변동(total variation)이 아니라 **곡선이 방향을 바꾸는 횟수**로
> 검증합니다. 이동평균은 단조 구간의 총변동을 바꾸지 않기 때문에, 그 지표로는
> 스무딩이 일하고 있는지 알 수 없습니다.

### 잔차 모니터

`output: 'residual'` 은 **제거될 성분만** 출력합니다. 거기서 음악이 들리면
과처리입니다. 게인이 `g` 와 `1−g` 로 나뉘므로 clean + residual 은 입력을 그대로
복원합니다 (테스트가 1e-4 이내로 확인).

## 2. De-click

### 탐지: 클릭은 불연속이다

클릭은 파형의 **불연속**이므로 탐지기는 2차 차분을 봅니다.

```
d[n] = |x[n] − 2·x[n−1] + x[n−2]|
```

부드러운 오디오는 아무리 커도 여기서 거의 아무것도 만들지 않고, 한 샘플의
점프는 스파이크를 만듭니다. 큰 소리와 클릭을 가르는 게 이 부분입니다.

### 그런데 스네어도 날카롭다

2차 차분만으로는 클릭과 스네어를 구분하지 못합니다. 구분자는 **지속시간**입니다.
클릭은 1–2 ms 안에 끝나고, 드럼 어택은 감쇠하면서 수십 ms 동안 고역에 에너지를
계속 밀어 넣습니다. 그래서 후보는 **날카롭고 동시에 짧아야** 합니다 —
`maxWidthMs` 검사가 복원기가 드러머를 잡아먹지 않게 막는 유일한 장치입니다.

> 셀프테스트가 감쇠하는 드럼 히트 두 개에 대해 **0개 검출**을, 그 위에 얹은
> 클릭 하나에 대해 **정확히 1개 검출**을 확인합니다.

### 복원: AR 모델을 풀어 배음을 되쓴다

50–150 샘플짜리 구멍을 매끄러운 곡선으로 이으면 들리는 둔한 자국이 남습니다 —
그 몇 밀리초 동안 수백 Hz 위의 모든 배음이 사라지기 때문입니다.

고전적인 해법이 **Janssen 보간**입니다. 구멍 주변 오디오에 자기회귀(AR) 모델을
맞추고, 그 모델의 예측 오차를 최소화하는 샘플들을 풀어냅니다. 보간 결과가 주변과
같은 배음을 갖는 이유는, 모델이 주변에서 만들어졌기 때문입니다.

구현 세부 세 가지가 결과를 좌우합니다.

* **훈련 데이터를 이어 붙이지 않는다.** 알려진 오디오는 구멍 *앞* 조각과 *뒤*
  조각입니다. 둘을 concat 하면 훈련 데이터 한가운데에 계단 불연속이 생기고,
  모델은 음악 대신 그 계단을 설명하는 데 차수를 씁니다. `lpcFromSegments` 가
  각 조각의 자기상관을 따로 계산해 더합니다. (이걸 고치자 오차 64 % → 8.9 %)
* **컨텍스트 창이 지배적이다.** 창이 가장 낮은 음의 **여러 주기**를 덮어야
  자기상관이 기본 주파수를 봅니다. 기본값 32 × order ≈ 23 ms 는 85 Hz 보컬의
  두 주기, 220 Hz의 다섯 주기입니다. (짧은 컨텍스트 7.6 % vs 기본값 1.8 %)
* **Janssen 반복.** 첫 추정 후, 방금 채운 샘플을 **포함해** 모델을 다시
  맞춥니다. 모델과 채움이 서로에게 수렴합니다. 2–3 패스에서 멈춥니다.

모델이 폭주하면(주변 최대치의 4배를 넘으면) 큐빅 에르미트로 물러납니다. 둔한
자국이 새 클릭보다 나은 실패입니다.

### 스테레오는 한 번만 탐지한다

디스크의 클릭은 양 채널을 함께 때립니다. 채널마다 탐지하면 서로 조금 다른
위치를 복원해서, 클릭 하나가 **스테레오 아티팩트**로 바뀝니다. 그래서 모노 합에서
한 번 탐지하고 같은 위치를 양쪽에 적용합니다.

## 세션 편집으로서

`daw/edit/restore-actions.ts` 의 모든 동작은 고친 오디오를 **새 소스 파일**로
쓰고 클립의 `fileId` 만 바꿉니다. 원본은 손대지 않으므로 undo 는 포인터
이동이고, 가져온 테이크는 절대 덮어써지지 않습니다. 스펙트럴 리페어와 같은
경로(`writeEditedClip`)를 공유합니다.

## UI

RESTORE 창. 노이즈 학습 구간은 **Edit 창의 시간 선택**을 그대로 씁니다 — 트림이나
페이드에 쓰는 바로 그 선택이라, 새 선택 UI를 배울 필요가 없습니다.

## 테스트

```
pnpm --filter @aimaster/desktop test:restore
```

20개 검사. 실제로 측정합니다 — 히스를 얹은 톤의 SNR이 8 dB 이상 개선되고 톤은
70 % 이상 살아남는지, 감쇠량이 단조 증가하는지, clean + residual 이 입력을
복원하는지, 드럼은 검출되지 않고 클릭만 검출되는지, LPC 예측 오차가 신호의
1 % 미만인지, 32 샘플 구멍 복원 오차가 원본 에너지의 2 % 미만이고 구멍을 그냥
두는 것보다 50배 나은지, 2.2 ms 구멍에서 AR이 큐빅보다 3배 정확한지.

## 아직 없는 것

De-hum (50/60 Hz 하모닉 제거) 과 De-reverb. 험 제거는 이미 있는 STFT 위에서
하모닉 빗살 감산으로 바로 얹을 수 있습니다.
