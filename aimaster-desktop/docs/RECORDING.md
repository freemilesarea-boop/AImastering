# Recording

Pro Tools 뼈대에서 마지막으로 비어 있던 칸입니다. 편집·라우팅·믹싱·오토메이션은
이미 있었고, 이제 소리를 **넣을** 수 있습니다.

---

## 세 가지 개념을 분리한다

### 프리롤과 카운트인은 다른 것이다

많은 DAW의 녹음 패널이 헷갈리는 이유가 이 둘을 뭉뚱그리기 때문입니다.

* **프리롤(Pre-roll)** — 테이프를 일찍 굴립니다. 트랜스포트가 펀치 지점보다
  앞에서 시작해 연주자가 앞 마디를 듣고 들어옵니다. **그 구간도 녹음되지만
  커밋할 때 잘립니다** — 캡처 중에 버리면 나중에 되찾을 수 없기 때문입니다.
* **카운트인(Count-in)** — 트랜스포트가 **움직이기 전에** 무음 위로 클릭이
  울립니다. 타임라인 위치는 하나도 움직이지 않습니다.

셀프테스트가 이걸 못 박습니다: 카운트인 2마디를 켜도 `transportStartSec` 과
`recordStartSec` 은 그대로 6초입니다.

### 펀치는 모드가 아니라 창(window)이다

녹음에는 언제나 시작이 있습니다. 펀치는 거기에 **끝**을 하나 더 줄 뿐이고,
같은 `RecordPlan` 이 두 경우를 모두 기술합니다. 그래서 "펀치 모드" 같은 분기가
코드에 없습니다.

펀치가 켜져 있으면 재생 헤드는 무시됩니다 — **펀치 지점이 곧 위치**입니다.
구간을 거꾸로 잡아도 정규화되고, 길이가 0이면 펀치가 아닌 것으로 취급해
재생 헤드로 되돌아갑니다.

### 루프 한 바퀴가 한 테이크다

캡처는 하나의 연속된 스트림이고, 타임라인이 감깁니다. 감기는 지점에서 스트림을
자르고 각 조각에 자기 플레이리스트를 주면 그게 루프 녹음의 전부입니다 —
그리고 **컴핑은 이미 플레이리스트를 다룰 줄 압니다.**

```
loopPasses(recordStart, capturedSec, loop) → LoopPass[]
```

* 0번 패스는 녹음이 시작된 곳부터 루프 끝까지. 루프 중간에 펀치했다면 짧습니다.
* 이후 패스는 전부 루프 시작점에 놓이는 온전한 한 바퀴.
* 마지막 패스는 실제로 녹음된 길이로 잘립니다.
* 100 ms 미만의 꼬리는 버립니다 — 멈춘 사이클의 부스러기지 테이크가 아닙니다.
  **단 0번 패스는 아무리 짧아도 남깁니다.** 그건 연주자가 의도한 것입니다.

## 캡처 경로

```
getUserMedia → MediaStreamAudioSourceNode ─┬→ daw-recorder.worklet (싱크)
                                           └→ (모니터링 시) 트랙 채널 입력
```

### 워클릿을 쓰는데 왜 "네이티브 노드만" 규칙이 안 깨지나

이 엔진의 규칙은 라이브와 오프라인 렌더가 동일하도록 신호 경로에 네이티브
노드만 두는 것입니다. 레코더 워클릿은 **싱크**입니다 — 아무도 그 출력을 읽지
않고, 지나가는 오디오를 건드리지도 않습니다. 샘플을 복사해 내보내기만 하는
탭은 들리는 것을 바꾸지 않습니다.

워클릿 안에서 4096 프레임 블록으로 모았다가 내보냅니다. 렌더 쿼텀은 128
프레임이라 매번 보내면 채널당 초당 375개의 메시지가 되고, 그 structured-clone
비용은 바쁜 그래프에서 글리치로 나타납니다.

워클릿에 목적지가 없으면 pull 이 보장되지 않으므로, 탭은 무음 게인 노드로
끝맺습니다.

### 브라우저 처리는 전부 끕니다

`echoCancellation`, `noiseSuppression`, `autoGainControl` 은 통화용입니다.
조용한 연주를 게이팅하고 큰 연주를 덕킹합니다. 기본값 off.

### 모니터링은 캡처와 별개의 결정

입력은 무장하면 열리고, 모니터링은 **따로** 켭니다. 켜면 트랙의 채널 입력으로
들어가므로 연주자가 **자기 인서트를 통과한 소리**를 듣습니다.

## 테이크가 되는 순간

```
commitRecording(session, trackId, captured, plan, settings) → { session, file, takes }
```

* 프리롤을 잘라내고, 펀치 아웃 뒤로 넘어간 꼬리도 잘라냅니다 (틱 루프가
  최대 한 틱 늦게 멈추므로 실제로 넘어갑니다).
* **파일은 하나만 씁니다.** 패스마다 파일을 쓰면 20테이크 보컬의 디스크 비용이
  20배가 되는데, 클립은 이미 자기 오프셋과 길이를 들고 있습니다. 테이크는
  같은 파일의 다른 지점을 가리키는 클립입니다.
* 각 패스가 자기 플레이리스트를 갖고, **마지막 패스가 활성 테이크**로 남습니다 —
  테이프 오퍼레이터가 할 일과 같습니다.
* 캡처한 샘플을 그대로 오디오 캐시에 심으므로 디코드 왕복 없이 파형이 바로
  그려집니다.

빈 테이프나 프리롤만 있는 테이프는 **에러로 거절**합니다. 빈 클립을 만드는 것보다
낫습니다.

## 상태 기계

불리언 조합에서 유도하는 대신 이름을 붙였습니다.

| 상태 | 뜻 |
|---|---|
| `idle` | 무장 없음, 입력 닫힘 |
| `armed` | 입력 열림, 모니터링 중, 트랜스포트 자유 |
| `countIn` | 클릭 재생 중, 트랜스포트 정지 |
| `recording` | 트랜스포트 진행, 테이프 회전 |
| `committing` | 파일 쓰고 테이크 배치 중 |

테이크는 오직 `recording` 에서만 커밋되고, 입력은 오직 `disarm` 한 경로로만
닫힙니다 — 반쯤 열린 마이크에 도달할 수 없습니다.

## 아직 하지 않는 것

* **한 번에 한 트랙.** 모델은 여러 트랙 무장을 허용하지만 `canRecord` 가
  거절합니다. 여러 입력을 동시에 캡처하는 건 별도의 작업입니다.
* **MIDI 녹음.** 인스트루먼트 트랙 무장은 명시적으로 거절합니다.
  MIDI 2.0 모델은 이미 있으니 라이브 입력 캡처만 붙이면 되지만, 오디오 녹음과는
  다른 경로입니다.

둘 다 조용히 실패하지 않고 **이유를 말하고 거절**합니다.

## 단축키

| 기능 | 단축키 |
|---|---|
| 녹음 무장 / 해제 | `R` |
| 녹음 시작 / 정지 | `Numpad *` 또는 `Mod+R` |
| 선택 구간을 펀치로 | `Mod+Shift+P` |

`Numpad *` 는 마스터링 앱에서는 여전히 "녹음 트랙이 없다"고 말합니다. DAW
워크스페이스가 떠 있을 때만 오버라이드로 녹음을 시작합니다 — Space 가 세션을
재생하는 것과 같은 방식입니다.

## 테스트

```
pnpm --filter @aimaster/desktop test:record
```

28개 검사. 마이크가 필요한 부분은 뺐고, **캡처가 무엇을 뜻하는지**를 결정하는
부분은 전부 들어갑니다 — 프리롤이 펀치를 움직이지 않는지, 카운트인이 타임라인을
움직이지 않는지, 루프 중간 펀치가 짧은 첫 패스를 만드는지, 꼬리 부스러기는
버리고 첫 패스는 남기는지, 커밋이 프리롤을 정확히 잘라내는지(램프 신호라
잘린 지점의 샘플 값으로 확인), 루프 3패스가 **파일 하나**와 레인 셋을 만드는지.
