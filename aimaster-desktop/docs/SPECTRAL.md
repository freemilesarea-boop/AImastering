# Spectral Repair & Mastering Reference

두 기능은 같은 뿌리(FFT/STFT)를 쓰지만 목적이 다릅니다.
**Spectral Repair** 는 "이 소리를 없애라", **Mastering Reference** 는 "이 곡처럼
만들어라" 입니다.

---

## 1. Spectral Repair

### 왜 스펙트로그램인가

파형 편집은 *언제* 만 답할 수 있습니다. 보컬 아래에 깔린 딸깍 소리는
*언제 + 스펙트럼 어디* 를 함께 지정해야 지울 수 있습니다. 그래서 클립을
주파수 × 시간 평면으로 그리고, 사용자가 문제 구간을 박스로 감싼 뒤 세 가지
동사 중 하나를 적용합니다.

| 동사 | 하는 일 |
|---|---|
| **REPAIR** | 박스 양옆 프레임에서 스펙트럼을 보간해 안을 다시 만듭니다. 클릭은 사라지고 그 아래 음은 계속 울립니다. |
| **ATTENUATE** | 박스를 N dB 만큼 내립니다. 외과적 노치. |
| **REPLACE** | 같은 대역을 테이크의 다른 시점에서 복사해 붙입니다. |

### 되돌릴 수 있는 변환이어야 한다

편집이 성립하려면 **선택하지 않은 부분은 그대로 돌아와야** 합니다.
그래서 STFT 는 weighted overlap-add 로 구현되어 있습니다 — 분석과 합성 양쪽에
Hann 창을 걸고, 창 제곱의 합(75 % 오버랩에서 1.5)으로 나눕니다. 셀프테스트가
왕복 오차 < 1e-5 를 검증합니다.

### 편집을 자연스럽게 만드는 세 규칙

* **페더링** — 딱 떨어지는 박스는 링잉을 만듭니다. 시간축·주파수축 경계에서
  가중치가 raised-cosine 으로 올라옵니다. 페더는 박스의 절반을 넘지 않습니다
  (넘으면 작은 선택이 가운데서도 완전히 감쇠되지 않습니다).
* **위상 보존** — magnitude 만 다시 씁니다(REPLACE 는 원본 위상을 가져옵니다).
  잔향/노이즈 플로어의 질감이 유지됩니다.
* **부분 변환** — 4분짜리 파일의 30 ms 클릭은 30 ms 만큼만 FFT 합니다.
  편집 구간 앞뒤로 2 프레임 패딩을 두고, 이어 붙일 때 짧은 크로스페이드를 겁니다.

### 창 길이

그리기는 2048 포인트(주파수 해상도), **편집은 1024 포인트**가 기본값입니다.
44.1 kHz 에서 2048 창은 8 ms 틱을 46 ms 로 번지게 하므로, 문제보다 훨씬 큰
박스를 그려야 합니다. 클릭 제거는 시간 해상도가 생명입니다.

### 의심 지점 (자동 탐지)

`findAnomalies()` 는 대역 제한(기본 2 k–16 k) 스펙트럴 플럭스의 국소 최대를
찾습니다. 분석 창의 제로 패딩과 겹치는 앞뒤 프레임은 제외합니다 — 그건 소재의
클릭이 아니라 우리 분석의 인공물이기 때문입니다.

### 세션 편집으로서의 리페어

`repairClipSpectrum()` 은 고친 오디오를 스크래치 디렉터리에 쓰고 새 소스 파일로
등록한 뒤 클립의 `fileId` 만 바꿉니다. 원본 파일은 손대지 않으므로 **undo 는
포인터 이동**이고, 가져온 테이크는 절대 덮어써지지 않습니다.

### 파일

| 파일 | 역할 |
|---|---|
| `daw/audio/fft.ts` | radix-2 in-place FFT, twiddle/bit-reversal 캐시, Hann 창 |
| `daw/audio/stft.ts` | 가역 STFT/ISTFT, bin↔Hz, 켤레대칭을 지키는 `setBin`/`scaleBin` |
| `daw/audio/spectral-edit.ts` | 세 동사, 페더링, 부분 변환, 그리기 그리드, 이상 탐지 |
| `daw/edit/spectral-repair.ts` | 클립에 적용 → 새 파일 등록 → `fileId` 교체 |
| `components/daw/spectral/SpectralEditor.tsx` | 스펙트로그램 캔버스 · 박스 드래그 · 의심 지점 |

## 2. Mastering Reference System

레퍼런스 트랙을 넣으면 논쟁이 숫자 일곱 개와 오버레이 네 개로 바뀝니다.

```
              REFERENCE      YOUR MIX
     LUFS       -8.7          -11.2
     TP         -1.0           -0.8
     DR          7.2            9.8
     WIDTH      118 %           92 %
     LOW         +0            +2.1
     MID         +0            -0.8
     HIGH        +0            -1.7
```

### 두 가지 원칙

* **음색 수치는 레벨 정규화** — 조용한 믹스가 어두운 믹스는 아닙니다. 모든
  스펙트럼은 광대역 레벨이 0 dB 가 되도록 오프셋된 뒤 비교됩니다. 그렇지 않으면
  LOW/MID/HIGH 가 LUFS 차이를 세 번 반복할 뿐입니다. (셀프테스트: 마스터를
  −6 dB 내리면 LUFS·TP 만 움직이고 음색 행은 그대로.)
* **라우드니스는 기존 미터 그대로** — `audio/loudnessCore.ts` 의 BS.1770-4
  구현을 재사용합니다. 미터는 하나, 진실도 하나.

### 각 수치의 정의

| 행 | 정의 | 허용 오차 |
|---|---|---|
| LUFS | BS.1770-4 게이팅 통합 라우드니스 | ±0.5 |
| TP | 4× 오버샘플 트루 피크 | ±0.3 |
| DR | Peak-to-Loudness Ratio (TP − LUFS) | ±1 |
| WIDTH | `100 × (1 − 상관도)` · 모노 0 %, 무상관 100 %, 역위상 200 % | ±10 |
| LOW / MID / HIGH | 20–250 / 250–4 k / 4 k↑ Hz, 레벨 정규화 후 차이 | ±1 dB |

MATCH 점수는 각 행이 허용 오차 안이면 1점, 벗어난 만큼 감점(허용 오차의 3배를
넘으면 0점)한 평균입니다.

### 오버레이

| 탭 | 그리는 것 |
|---|---|
| FREQUENCY | 두 곡의 레벨 정규화 스펙트럼(48밴드 로그 간격), ±24 dB |
| DYNAMICS | 각자의 integrated 기준으로 정렬한 short-term LUFS — 라우드니스가 아니라 **다이내믹스의 모양**을 비교 |
| STEREO | 대역별 폭(0–200 %). mid/side 파워비 k 에서 상관도 = (1−k)/(1+k) |
| TONAL BALANCE | 믹스 − 레퍼런스 차이 곡선. 실제로 EQ 를 걸 대상 |

### 제안

`matchSuggestions()` 가 델타를 문장으로 바꿉니다 — "800 Hz 부근을 1.2 dB
줄이세요", "리미터를 풀어 2.1 dB 더 열어주세요" 처럼 바로 실행 가능한 형태로.

### 파일

| 파일 | 역할 |
|---|---|
| `daw/analysis/reference.ts` | 평균 스펙트럼, 대역 레벨, 상관도/폭, 전체 분석, 비교, 제안 |
| `stores/referenceStore.ts` | 분석 결과 두 개(버퍼 아님)와 비교 결과 보관 |
| `components/daw/reference/ReferencePanel.tsx` | 표 · 오버레이 4탭 · 제안 목록 |
