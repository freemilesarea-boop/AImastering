# Device Chain · Rack · Session View

Ableton 에서 가져올 가치가 있는 세 가지. 공통점은 **보이지 않는 것을 보이게
만든다**는 점입니다.

- 모델: `src/renderer/daw/model/device-graph.ts`, `racks.ts`, `session-view.ts`
- 엔진: `src/renderer/daw/engine/device-chain.ts`
- UI: `src/renderer/components/daw/chain/`, `session/`
- 테스트: `pnpm --filter @aimaster/desktop test:ableton` (28 checks)

## 1. Device Chain

플러그인을 슬롯 목록이 아니라 **그래프**로 모델링했습니다. 목록으로는
엔지니어가 실제로 만드는 구조를 표현할 수 없기 때문입니다.

```
INPUT
  │
  ▼
DENOISE
  │
  ▼
EQ ──────► PARALLEL SAT
  │              │
  ▼              │
COMP ◄───────────┘
  │
  ├────► REVERB SEND
  │
  ▼
LIMIT
```

`Mod+Alt+H` → CHAIN 탭.

### 그래프가 엔진에 1:1로 대응합니다

| 모델 | WebAudio |
|---|---|
| 노드 | 입력 합산 GainNode + 플러그인 인스턴스 |
| 엣지 | `source.output → 엣지 게인 → target.input` |
| 팬아웃(병렬 분기) | 한 출력에서 여러 연결 — WebAudio 가 그대로 분배 |
| 팬인(병합) | 한 입력에 여러 연결 — WebAudio 가 그대로 합산 |
| 센드 노드 | 입력을 버스로 탭하고 하류로 이어지지 않음 |
| 랙 노드 | 같은 빌더를 랙 내부 그래프에 재귀 적용 |

병렬 처리에 특별한 코드가 없습니다. 병렬 새츄레이션은 그냥 **EQ 에서 나가는
엣지 2개와 COMP 로 들어오는 엣지 2개**입니다. 블렌드 레벨은 엣지의 게인이고요.

### 안전장치

- 피드백이 되는 케이블은 **연결 자체를 거부**합니다 (채널 내부 피드백은 사고)
- 디바이스를 지우면 경로를 **이어 붙입니다** — 컴프를 지웠다고 채널이 죽지 않음
- 검증이 두 가지 무음 원인을 잡습니다: 출력까지 이어지지 않음 / 막다른 디바이스
- 레이아웃의 "메인 경로"는 각 노드에서 **가장 먼저 만든 케이블**을 따라갑니다.
  브랜치는 나중에 추가되므로, 만든 사람이 생각한 그 경로와 일치하고 안정적입니다
- 룩어헤드 지연은 **가장 긴 경로** 기준으로 계산돼 지연 보정에 들어갑니다

### 오프라인 디바이스

피치 보정처럼 파일 전체를 봐야 하는 디바이스는 실시간 그래프에서 돌 수
없습니다. 조용히 아무 일도 안 하는 대신 체인에 **OFFLINE 배지**로 남고,
렌더 경로에서 적용됩니다.

## 2. Rack

```
LOUI VOCAL RACK
  DENOISE → PITCH → DYN EQ → COMP → DE-ESSER → SATURATION → AIR

  사용자에게는:
  CLEAN     ●──────
  BODY      ───●───
  PRESENCE  ────●──
  AIR       ─────●─
```

Logic Smart Control + Ableton Rack 의 결합입니다. 랙 노드를 더블클릭하면
네 개 노브가 나오고, **열기** 를 누르면 안쪽 디바이스 전부와 매핑이 보입니다.

- 매핑은 Ableton 방식(**from → to 범위**)입니다. 그래서 PRESENCE 하나가
  컴프 레이시오는 올리고 어택은 동시에 줄일 수 있습니다.
- **한 파라미터의 주인은 하나뿐**입니다. 다른 매크로를 같은 파라미터에
  매핑하면 앞의 매크로에서 자동으로 떨어져 나갑니다 — 두 노브가 한 값을
  두고 싸우는 건 귀로만 알 수 있는 버그라서요.
- 채널 레벨의 매크로(WARMTH/PUNCH/…)는 여러 매크로가 파라미터를 공유하므로
  **가산 델타** 방식이고, 랙 내부는 매핑이 파라미터를 독점하므로 **범위**
  방식입니다. 의도적으로 다릅니다.

내장 블루프린트: `LOUI VOCAL RACK`, `LOUI DRUM RACK`.

## 3. Session View

```
        Scene A   Scene B   Scene C
Drum       ●         ●         ●
Bass       ●         ●
Piano      ●                   ●
Synth                ●         ●
Vocal      ●
```

`Mod+Alt+Y` → SESSION 탭.

- 클립을 누르면 **다음 마디**에 시작합니다 (그전까지 셀은 QUEUED)
- 트랙당 한 클립만 재생 — 다른 셀을 누르면 자리를 넘겨받습니다
- 씬 실행은 그 행 전체. 그 씬에 클립이 없는 트랙은 **하던 걸 계속**합니다
- 정지도 양자화됩니다
- Session 클럭은 **타임라인 트랜스포트와 독립**입니다. 편곡을 멈춰둔 채로
  잼을 할 수 있어야 클립 런처의 의미가 있으니까요

### Arrangement 로 변환

씬 순서와 마디 수를 정하고 한 번 누르면 **진짜 클립**이 타임라인에 놓입니다.
1마디 루프는 8마디 구간을 채우도록 반복되고, **마지막 반복은 구간을 넘지
않도록 잘립니다**. 그 시점부터는 이 앱의 나머지 편집기가 전부 붙습니다.

## 4. 검증

```
pnpm --filter @aimaster/desktop test:ableton      # 그래프 · 랙 · 세션 (28)
pnpm --filter @aimaster/desktop test:daw-engine   # 실제 렌더 (23)
```

렌더로 증명한 것:
- 유니티 병렬 브랜치 2개가 **정확히 2배**로 합쳐지는가, −6 dB 블렌드는 1.5배인가
- 센드 노드가 메인 경로를 건드리지 않고 리턴만 더하는가
- 랙이 내부 체인을 렌더하고, BODY 매크로가 소리를 바꾸는가

로직으로 고정한 것:
- 케이블에 디바이스를 떨구면 그 자리에 끼어드는가
- 디바이스를 지우면 경로가 이어지는가
- 병합 노드가 위상 정렬에서 **두 소스보다 뒤**에 오는가
- 피드백 케이블이 거부되는가
- ASCII 다이어그램이 브랜치를 `├────►` 로 그리는가
- 랙 매크로가 from → to 로 움직이고, 재매핑이 이전 주인을 뗴어내는가
- 런치가 마디 경계 전에는 시작하지 않는가
- 씬 실행이 빈 슬롯 트랙을 건드리지 않는가
- 변환이 루프를 채우고 마지막을 자르는가

## 5. 남은 작업

1. 체인 뷰에서 케이블을 **드래그로 다시 연결**하기 (현재는 삽입/삭제/브랜치 버튼)
2. 사용자 랙 저장 · 불러오기 (블루프린트는 내장 2종)
3. Session 클립 녹음 (현재는 타임라인 클립을 슬롯에 넣는 방식)
4. 씬별 템포/박자 전환 (모델에는 자리가 있음)
5. 오프라인 디바이스를 바운스 경로에 자동 적용 (현재는 VariAudio 명령으로 수동)
