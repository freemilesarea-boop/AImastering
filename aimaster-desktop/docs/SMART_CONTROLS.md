# 스마트 컨트롤 · 트랙 스택 · 디자인 시스템

Logic 에서 가져온 것은 기능이 아니라 **UX 철학**입니다.

> 초보자와 엔지니어가 같은 프로그램을 쓴다.

그러려면 두 가지가 동시에 참이어야 합니다.
노브 하나가 실제로 다섯 개를 움직여야 하고, 그 다섯 개를 **언제든 열어볼 수
있어야** 합니다. 열 수 없으면 블랙박스이고, 엔지니어는 블랙박스를 쓰지
않습니다.

- 모델: `src/renderer/daw/model/macros.ts`, `stacks.ts`
- UI: `src/renderer/components/daw/smart/`
- 디자인 토큰: `src/renderer/theme/premium.ts`
- 테스트: `pnpm --filter @aimaster/desktop test:macro` (30 checks)

## 1. Macro Control System

`Mod+Alt+S` 또는 믹서 스트립의 **SMART** 버튼.

일곱 개의 매크로가 여덟 개 모듈로 이루어진 랙을 움직입니다.

| 매크로 | 무엇을 움직이는가 |
|---|---|
| **WARMTH** | 새츄레이션 드라이브·믹스 ↑, EQ 로우 ↑, 하이 ↓, 컴프 어택 느리게 |
| **CLARITY** | 로우미드 ↓, 프레즌스 ↑, HPF ↑, 익사이터 살짝 |
| **PUNCH** | 트랜지언트 어택 ↑, 컴프 임계값 ↓·레이시오 ↑·어택 빠르게·메이크업 ↑, 어퍼미드 ↑ |
| **AIR** | 익사이터 양·주파수·믹스 ↑, 하이 셸프 ↑ |
| **WIDTH** | 사이드 게인 (양방향 — 좁히기도 함), 넓힐 때만 베이스 모노 |
| **DEPTH** | 공간 믹스·디케이·프리딜레이 ↑, 하이 살짝 ↓ |
| **LOUDNESS** | 리미터 실링 ↓, 컴프 임계값 ↓·메이크업 ↑, 릴리즈 빠르게 |

랙: `EQ → Saturation → Transient → Compressor → Exciter → Width → Space → Loudness`

### 설계 규칙

1. **매크로는 순수 함수다.** `materializeRack(rack)` 이 모든 결과 파라미터를
   돌려주고, 오디오 엔진과 Advanced 뷰가 **같은 함수**를 읽습니다.
   화면의 숫자가 곧 렌더되는 숫자입니다.
2. **매크로는 더해진다.** WARMTH 는 하이 셸프를 −1.8 dB, AIR 는 +2.2 dB
   움직입니다. 둘 다 올리면 +0.4 dB — 나중에 움직인 쪽이 앞의 것을 지우지
   않습니다. Advanced 에는 `WARMTH + AIR` 라고 표시됩니다.
3. **한 노브로는 망가진 소리에 도달할 수 없다.** 모든 결과값은 플러그인이
   선언한 범위로 클램프됩니다. 일곱 매크로를 전부 최대로 올려도 파라미터는
   유효 범위 안에 있습니다 (테스트로 고정).
4. **수동 조정이 이긴다.** Advanced 에서 값을 만지면 그 파라미터는 고정되고
   쿨 컬러로 표시되며, `↺` 로 매크로 값에 돌려줍니다. 매크로가 원래 주려던
   값도 옆에 남아 있습니다.
5. **아무 것도 건드리지 않은 모듈은 신호 경로에서 빠집니다.** CPU 도, 색깔도
   쓰지 않습니다.

### Advanced

모듈마다 모든 파라미터를 슬라이더 + 수치 + **어떤 매크로가 움직였는지**로
보여줍니다. 랙의 리미터 룩어헤드는 지연 보정에도 자동 반영됩니다.

## 2. Track Stack

```
VOCALS              ← 스택 (합산)
 ├ Lead
 ├ Double L
 ├ Double R
 ├ Harmony
 └ Adlib
```

`Mod+Shift+G` 로 선택 트랙을 묶습니다.

| | 폴더 스택 | 합산 스택 |
|---|---|---|
| 버스 | 없음 | 자동 생성, 멤버가 그리로 출력 |
| 스택 페이더 | 멤버에 VCA 처럼 적용 | 스택 채널 자체에 적용 (이중 적용 없음) |
| 스택 인서트 | — | 그룹 전체에 하나의 컴프 |
| 뮤트/솔로 | 멤버까지 전파 | 동일 |

- 스택 솔로 → 멤버가 살아 있음
- 멤버 솔로 → 그 스택도 소리를 통과시킴 (아니면 솔로가 안 들림)
- `Mod+Shift+F` 접기 — 접힌 스택은 멤버 클립을 요약해서 한 줄로 보여줍니다
- `Mod+Shift+U` 해제 — 멤버는 마스터로 되돌아가고 죽은 버스는 사라집니다
- 중첩 가능, 순환은 거부됩니다

## 3. 디자인 시스템

`theme/premium.ts` — 창작 판단을 내리는 화면(스마트 컨트롤, 콘솔, 스택 헤더)
전용 토큰입니다. 목표는 "대시보드"가 아니라 "악기".

| 규칙 | 이유 |
|---|---|
| 액센트는 **황동 하나** | 금색인 것은 전부 "사용자가 정한 값". 색이 장식이 아니라 정보가 됩니다 |
| 빛은 항상 위에서 | 모든 융기면은 위가 밝고, 그림자는 아래로. 물리적으로 일관돼야 고급스럽게 읽힙니다 |
| 엘리베이션은 면 + 그림자 | 테두리만으로 층을 만들지 않습니다 |
| 타이포: 디스플레이 세리프 + 좁은 산세리프 + 표 형태 숫자 | 모듈 이름은 각인된 패널처럼, 수치는 자릿수가 흔들리지 않게 |

**Knob** 컴포넌트는 하드웨어처럼 동작합니다: 세로 드래그(포인터 캡처),
Shift 미세 조정, Alt 로 기본값 스냅, 더블클릭 리셋, 휠, 방향키.
바이폴라 노브는 중앙에서 양쪽으로 아크가 자랍니다. 수동 조정된 값은 쿨
컬러로 그려져 매크로가 만든 값과 구별됩니다.

## 4. 검증

```
pnpm --filter @aimaster/desktop test:macro        # 매크로 + 스택 (30)
pnpm --filter @aimaster/desktop test:daw-engine   # 실제 렌더 (20)
```

숫자로 고정한 것:
- PUNCH 1개가 3개 모듈 · 7개 파라미터를 문서대로 움직이는가
- 커브(slowStart/fastStart)가 절반 지점에서 정확히 0.25 / 0.707 만큼 가는가
- 두 매크로가 같은 파라미터에서 **더해지는가**, 그리고 둘 다 크레딧되는가
- 일곱 매크로를 전부 최대로 올려도 **모든 값이 플러그인 범위 안**인가
- 오버라이드가 이기고, 표시되고, 리셋되는가
- 새츄레이션이 원본에 없던 **3차 배음을 실제로 만드는가** (렌더 후 측정)
- 와이드너가 사이드 신호를 넓히고 width 0 에서 모노로 접는가
- 매크로 랙이 소리를 바꾸고, 전부 0 일 때는 **투명한가**
- 스택 뮤트/솔로/페이더가 멤버에 정확히 전파되는가 (합산 스택은 이중 적용 없음)
