# @loui/dsp-wasm

WebAssembly build of `loui-dsp` (Rust DSP core).  This package contains
the post-processed output of `wasm-bindgen`, ready for consumption by
the desktop renderer and any future web client.

## Contents

| File | Purpose |
|---|---|
| `pkg/loui_dsp_wasm.js`            | ES module loader (`init()` + class exports) |
| `pkg/loui_dsp_wasm.d.ts`          | TypeScript declarations |
| `pkg/loui_dsp_wasm_bg.wasm`       | Compiled WebAssembly module (~99 KB) |
| `pkg/loui_dsp_wasm_bg.wasm.d.ts`  | TypeScript declarations for raw wasm exports |

## How to regenerate

The `pkg/` directory is **build output** — it is regenerated by the
script at `dsp-core/scripts/build-wasm-bindings.sh`.  Running it
requires:

- Rust toolchain (`rustup target add wasm32-unknown-unknown`)
- `wasm-bindgen-cli` (`cargo install wasm-bindgen-cli`)

```sh
cd aimaster-desktop
pnpm --filter @loui/dsp-wasm run build
# or directly:
bash dsp-core/scripts/build-wasm-bindings.sh
```

The script:
1. Builds `loui-dsp-wasm` for the `wasm32-unknown-unknown` target in release mode.
2. Runs `wasm-bindgen --target web` on the resulting `.wasm` file.
3. Copies the output into this package's `pkg/` directory.

## Usage (renderer)

```ts
import init, {
  LouiAnalyzer,
  LouiSpectrumAnalyzer,
  WasmSpectrumOptions,
  crateVersion,
} from '@loui/dsp-wasm';

// One-time init — fetches and instantiates the .wasm file.
// In Vite, the wasm path is auto-resolved by the loader.
await init();

const analyzer = new LouiAnalyzer(48_000, 2);
analyzer.processStereo(left, right);          // zero-copy Float32Array
const snap = analyzer.tickSnapshot();         // safe from audio thread
console.log(crateVersion(), snap.momentaryLufs);
```

## Why a separate workspace package

Keeps `apps/desktop` decoupled from the build location of the wasm
artifacts.  Future consumers (e.g. `apps/web`, plugin hosts) import the
same `@loui/dsp-wasm` without path acrobatics.

## Version pinning

`@loui/dsp-wasm@0.1.0` ↔ `loui-dsp@0.1.0` (M2-lite-NEXT) + FFT API
additions from M3-entry.  Bump together on any DSP behaviour change.
